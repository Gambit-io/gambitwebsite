How HOEM runs today

Systems and funnel map·For review before the deep dive on Wednesday, September 9, 2026

The student journey as it actually works right now, which system owns each step, where the work is still done by hand, and where Jarvis can plug in. Built from HOEM's own SOPs, templates and journey docs.

Done by hand today Jarvis hook Doc still missing (empty export)

1. Discover

Google Ads, GA, socials, TTC, fairs, agents

  • Word of mouth, TTC subway ads, Instagram / TikTok, housing fairs, Bonard (intl)
  • GA search terms sorted into keyword / exclusion lists by hand
  • "How did you hear about us" lives in scattered surveys
Answer first questions on-site, 24/7, any persona

2. Inquire

Website form → Rent Manager

  • Prospect created, set to "new prospect" stage
  • Daily leasing-board clean-up: duplicates, wrong stage
  • Occupancy numbers updated for team each morning
  • Prospect Strategy doc
Capture + qualify the lead, create the prospect cleanly

3. Nurture

Rent Manager templates, email

  • 3-email sequence: Welcome → Learn more → Ready to book?
  • Campaigns sent Mon / Wed / Fri by coordinator
  • "Hot leads" (repeat inquiries) flagged to front desk
  • Prospect Outreach staff instructions
Two-way conversation instead of one-way drip

4. Tour

Outlook Bookings (HOEMTours@)

  • Virtual or in-person, under 30 min, ambassador-led
  • 24h reminder + post-tour thank-you templates
  • Tour outcome transferred into Rent Manager by staff
  • Tour Transfer to Rent Manager doc
Book / reschedule tours, send reminders, follow up

5. Book

book-a-room portal, Rent Manager

  • Enter info → term + room → guarantor → sign agreement → pay
  • Needs proof of student status + guarantor
  • Next-day "RCL" audit checks every processed booking by hand
  • Cancellation / TYA guide
Guide to the portal, answer fee + roommate questions

6. Pay

Rotessa, POS, MS Forms

  • Installments via Rotessa (pre-authorized debit)
  • Payment plan: Form → jarvis@ inbox → tracker → Rent Manager → Rotessa
  • Front-desk POS payments
  • POS Payment Process guide
Explain options, intake payment-plan requests

7. Live

Mosino One app, front desk, jarvis@

  • Move-in, 24/7 front desk, events, Downtown Student
  • Mosino One: building access, visitor QR passes, turnstiles (Phase 1 rollout)
  • Front desk fields app setup questions
  • Short Stay & Groups checklists
Resident concierge: knows who you are, tone shifts

8. Renew

Portal, Rent Manager

  • Renewal campaign, loyalty perks, room choice
  • Returning student handled as existing resident, old prospect set to Lost
  • Duplicate prospect checks on returners
Renewal nudges, alumni + referral loop

The systems underneath

Rent Manager

The spine. Prospects, leasing board, contracts, resident profiles (UDFs), stages, email templates.

Owns stages 2, 3, 5, 6, 8. Every Jarvis "action" routes through here.

Rotessa

Recurring payments and installment schedules.

Owns stage 6.

Mosino One

Resident app already rolling out: access, visitor passes, turnstiles, Staff Hub.

Owns stage 7. The incumbent in the "resident app" question.

Microsoft 365

Outlook Bookings (tours), Forms (payment plans), SharePoint + Excel (trackers), Outlook mail incl. jarvis@hoem.ca.

Glue across 3, 4, 6, 7.

Google Ads + Analytics

Paid search and site analytics, managed by hand. No aggregated dashboard today.

Owns stage 1.

What this means for Jarvis

  • Personality, knowledge and guardrails can start now from the tour guide, brand guide and USPs.
  • Every real "action" (create prospect, book tour, move stage, payment plan) depends on what Rent Manager exposes.
  • Jarvis must know new prospect vs. current resident, and change tone accordingly.

Where automation is already waiting

  • The next-day RCL audit: catch errors at entry instead of after.
  • The five-step payment-plan handoff.
  • Nurture sending, leasing-board clean-up, hot-lead flagging.
  • Marketing attribution: one dashboard across channels and spend.
